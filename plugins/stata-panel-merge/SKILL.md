# Stata 웨이브 → Long 패널 병합

## 절차

1. **패널 ID·wave 식별** — 개인 ID가 무엇인지, wave가 파일로 나뉘어 있는지 변수로 있는지
2. **변수명 규칙 파악** — 웨이브 표식이 접두사인지 접미사인지, 자릿수(패딩) 몇 자리인지,
   문항 계열과 파생변수 계열이 따로 있는지, 시불변 변수는 무엇인지
3. **rename** — 웨이브 표식을 제거해 이름을 통일
4. **append** — union으로 쌓고 `xtset <id> wave`

변수명·파일명은 하드코딩하지 않는다. 매번 2단계에서 직접 파악해 채운다.

**변수는 전부 담는다(union).** 어떤 변수를 쓸지 미리 묻지 않는다. 합쳐두고 필요한
것만 빼서 분석하는 편이 낫다. 특정 웨이브에만 있는 문항은 다른 웨이브 행에서
결측이 되며, 그것이 정상이다.

---

## 반드시 지킬 것

- **StataMCP로만 수행한다.** pandas·pyreadstat 등으로 .dta를 읽지 않는다.
  값레이블/변수레이블 소실, 타입 승격 불일치, 확장결측(.a~.z) 손실이 발생한다.

- **`StataMCP:executeStata`(동기)로 실행한다. `executeStataAsync`를 쓰지 않는다.**
  파일이 크거나 변수가 많아 보여도 마찬가지다. 병합 작업은 각 단계의 출력(변수 목록,
  잔여 접두사 assert, 관측치 수)을 즉시 확인하고 다음 단계를 결정해야 하므로,
  결과를 못 보는 fire-and-forget 실행은 부적절하다.

- **Stata 명령어·옵션 문법이 확실하지 않으면 `StataMCP:getHelp`로 확인한다.**
  기억에 의존해 추측하지 않는다. 특히 `rename group`처럼 문법이 미묘한 명령은
  반드시 help를 먼저 읽는다. 문법/옵션 에러(rc≠0)가 났을 때도 곧바로 getHelp를
  호출한다.

- **`reshape long`을 쓰지 않는다.** 접두사형 변수는 stub이 수백~수천 개라
  reshape가 비현실적으로 느리다. rename + append로 처리한다.

- **접두사 제거는 `rename group`의 숫자그룹 문법을 쓴다.** 웨이브 번호를 코드에
  박지 않으므로 10차 이상도 안전하다. (`help rename group`)

  ```stata
  rename <파생접두사>(##)* d_*[2]     // w03edu → d_edu
  rename <문항접두사>(##)* *[2]       // y03c001 → c001
  ```

  `(##)`=정확히 2자리, `(#)`=1자리. 패딩 폭은 2단계에서 확인한 값을 쓴다.
  `*[2]`는 두 번째 토큰 참조 — 그냥 `*`를 쓰면 숫자그룹을 가리켜 실패한다.
  파생변수는 별도 접두사로 분리해 문항 stem과의 충돌을 막고, **파생 → 문항 순서**로
  rename한다.

- **rename 직후 잔여 접두사를 assert로 검증한다. 생략 금지.**

  ```stata
  capture ds <문항접두사>* <파생접두사>*
  assert "`r(varlist)'" == ""
  ```

  rename은 패턴이 안 맞아도 **에러 없이 매칭 0건으로 통과**한다 (패딩 폭 오판이
  대표적). 접두사가 붙은 채 append되면 변수만 몇 배로 불어난 그럴듯한 쓰레기가
  나온다. 이 assert가 그 조용한 실패를 잡는 유일한 장치다.

- **행은 배포된 원자료 그대로 유지한다.** 표본을 임의로 걸러내지 않는다.
  국내 패널은 웨이브 파일마다 원표본 전원의 행을 유지하고 미응답자를 빈 행으로 두는
  경우가 많다 → append 후 `tab wave`가 차수별로 균등한 것이 정상. 실제 표본은
  응답 플래그로 봐야 한다는 점을 사용자에게 알린다. 미응답자 제외는 분석 단계에서
  사용자가 판단한다.

- **`xtset`을 `save` 전에 실행한다.** xtset 설정은 데이터셋 characteristic으로
  기록되므로, xtset 후 저장하면 다음에 `use`만 해도 패널 설정이 살아 있다.
  저장 후에 xtset하면 파일에는 안 남는다.

- **원본 .dta를 덮어쓰지 않는다.** 새 파일명으로 저장한다.

- **실행 전 처리 방식과 do-file 초안을 제시하고 승인을 받는다.**

## 검증 (생략 금지)

append 직후:

```stata
isid <id> wave                                   // 패널 키 유일성
by <id>: assert <시불변변수> == <시불변변수>[1]     // 개인 내 일정한지
capture ds <문항접두사>* <파생접두사>*
assert "`r(varlist)'" == ""                      // 잔여 접두사 0건
tab wave <응답플래그>, m                          // 차수별 응답/미응답

xtset <id> wave                                  // 패널 구조 확정
xtdescribe                                       // 구조 요약 확인
compress
save "<새 파일명>", replace                       // ← xtset 이후에 저장
```

저장한 파일을 다시 열어 설정이 실제로 남았는지 확인한다:

```stata
use "<새 파일명>", clear
xtset                                            // 인자 없이 → 저장된 설정 출력
```

`xtset`이 "strongly balanced"로 나와도 미응답 행이 유지된 결과일 수 있다.
실제 응답 인원(`tab wave if <응답플래그>==1`)을 함께 보고한다.
